## 一、全局规范

### 1.0 产品定位
- 1Life 的核心卖点是**营养健康与运动健身**：帮助用户记录饮食营养、理解每日摄入与活动消耗、管理减脂/增肌/维持/均衡目标。
- 饮食记录、营养目标、用户自建食物/模板、AI 拍照识别、Apple Health 动态 TDEE 是核心能力。
- 日志和习惯是辅助模块：日志用于补充心情、压力、睡眠、身体感受和训练复盘；习惯用于轻量追踪喝水、拉伸、训练、早睡等行为。
- 产品表达应避免把 1Life 定位成泛生活管理 App；它是健康和健身场景下的个人记录与分析工具。

### 1.1 语言
- 支持：简体中文、English
- 跟随系统语言自动切换
- 用户可在设置中手动覆盖
- 后续版本考虑加入 Español、Français

### 1.2 外观
- 支持系统浅色 / 深色 / 跟随系统（三选一）
- 颜色与图标由设计师统一定制，用户不可自选主题色

### 1.3 交互规范
- 所有破坏性操作（删除、清空数据）需二次确认
- 成功操作提供轻触觉反馈（Haptic）
- 网络请求失败需有明确错误提示

### 1.4 无障碍
- 支持 Dynamic Type
- 所有图标配有 accessibilityLabel
- 支持 VoiceOver

### 1.5 隐私
- 所有数据存储在用户设备本地（SwiftData）
- AI API Key 存入 iOS Keychain，不经过任何第三方服务器
- 食物照片仅存储在本地，不上传至除 AI 服务商以外的任何服务器
- AI 拍照识别时，照片发送至用户选择的 AI 服务商进行识别，隐私政策中明确说明

## 二、Onboarding 入门流程

> 仅首次启动显示，完成后不再出现。可在设置中重新触发部分步骤。

**导航行为**：
- 顶部进度指示器（圆点或细线）显示当前步骤
- 「下一步」按钮在底部，「返回」按钮在左上角（或支持左滑返回）
- 可自由前后切换步骤，已填写的内容保留
- 「可跳过」步骤的跳过按钮在「下一步」按钮旁边或下方

### 2.1 欢迎页
- App Logo + Slogan
- 三个核心价值点展示（拍照识别 / 营养追踪 / 智能分析）
- 按钮：「开始设置」

### 2.2 语言选择
- 列出支持的语言供点击选择
- 选中后界面立即切换为对应语言
- 底部「下一步」

### 2.3 个人资料
- 头像选择（PhotosPicker，家族标准 UserAvatarView）
- 昵称输入
- 底部「下一步」

### 2.4 身体参数（可跳过）
- 性别选择（男 / 女）
- 年龄（数字输入或滚轮选择）
- 身高（cm）
- 体重（kg）
- 活动水平（久坐 / 轻度活动 / 中度活动 / 重度活动）
- 这些参数用于通过 Mifflin-St Jeor 公式估算基础代谢率（BMR）和每日总消耗（TDEE），为下一步热量目标提供个性化推荐
- 跳过时使用通用默认值（2,000 kcal）
- 所有参数后续可在设置中修改

### 2.5 饮食目标
- 四个目标卡片供选择：
  - **减脂**：推荐 TDEE × 0.8，蛋白质偏高，碳水适中
  - **增肌**：推荐 TDEE × 1.15，蛋白质高，碳水高
  - **维持**：推荐 TDEE × 1.0，三大宏量素均衡
  - **均衡饮食**：不设严格目标，重在记录
- 如果上一步填写了身体参数，每张卡片显示**个性化**的每日热量推荐值和宏量素比例
- 如果跳过了身体参数，显示通用推荐值
- 单选，默认高亮「均衡饮食」

### 2.6 每日热量目标
- 根据身体参数 + 饮食目标自动计算推荐值
- 用户可手动调整
- 同时显示推荐的三大宏量素目标（蛋白质 g / 碳水 g / 脂肪 g）
- 可跳过，使用推荐值

### 2.7 提醒节奏
- 三餐提醒时间选择：
  - 早餐提醒：默认 08:00
  - 午餐提醒：默认 12:00
  - 晚餐提醒：默认 19:00
- 每个提醒可独立开关
- 可跳过

### 2.8 AI 配置（可跳过）
- 说明：AI 帮你拍照识别食物、记录饮食
- 选择 AI 服务商：Claude / ChatGPT(OpenAI API) / Kimi / 通义千问 / 豆包 / 腾讯混元 / DeepSeek / 小米 MiMo
- 输入对应 API Key
- 「测试连接」按钮
- 底部「跳过，稍后设置」/「完成」

### 2.9 设置完成页
- 展示设置摘要：饮食目标、每日热量目标、提醒设置
- 「开始记录」按钮

## 三、首页（Today Dashboard）

### 3.1 顶部日期导航
- 显示「M月D日 周X」格式
- 左右箭头切换天
- 右箭头在今天禁用
- 点击日期标题可跳出日历选择器

### 3.2 英雄卡片（Hero Card）
- 圆形进度环：今日摄入热量 / 目标热量
- 中心大字号热量数字：`1,240 / 2,000 kcal`
- 进度环颜色：0-80% 主色，80-100% 橙色，100%+ 红色。「均衡饮食」模式下进度环全程使用主色不变红（因为不是严格目标），目标数字旁标注「参考」二字
- 进度环下方三条宏量素进度条：
  - 蛋白质：`当前g / 目标g`，固定蓝色
  - 碳水化合物：`当前g / 目标g`，固定橙色
  - 脂肪：`当前g / 目标g`，固定黄色

### 3.3 营养素详细列表
- **默认折叠**，只显示「查看全部营养素 ▾」按钮。点击展开。英雄卡片已经展示了三大宏量素，展开是给需要更细粒度的用户用的。减少首页默认高度，避免小屏设备需要滚动 3-4 屏。
- 展开后位于英雄卡片下方
- 每行：营养素名称 + 当前值 + 目标值 + 迷你进度条
- 追踪的营养素：
  - 三大宏量素：蛋白质、碳水化合物、脂肪（已在英雄卡片展示，此处可省略或重复）
  - 膳食纤维（g）
  - 钠（mg）
  - 糖（g）
  - 胆固醇（mg）
- 超标项进度条变红，不足项保持默认色

### 3.4 今日三餐概览
- 紧凑的横向摘要条（不是完整卡片，避免与饮食页重复）
- 每个餐次显示：图标 + 总热量数字，一行排开
- 已记录的餐次正常展示，未记录的显示「—」
- 整条可点击 → 跳转饮食页
- **与饮食页的边界**：首页只展示每餐的一个热量数字（摘要级），不展示食物明细。食物明细是饮食页的职责。

### 3.5 饮水进度卡片
- 紧凑一行展示：水滴图标 + `1,250 / 2,000 ml` + 「+1杯」快捷按钮
- 点击「+1杯」直接创建一条 WaterLog（默认 250ml），轻触觉反馈
- 点击后底部显示 3 秒 SnackBar：「已记录 250ml · 撤销」。点击撤销则删除刚创建的 WaterLog
- 长按「+1杯」可选择其他量（一瓶 500ml / 自定义）
- 每日目标可在设置中修改

### 3.6 习惯完成度卡片
- 紧凑展示：「今日习惯 3/5 完成」
- 布尔型习惯（如「冥想」）：图标 + 名称 + 勾选按钮，点击直接完成
- 数量型习惯（如「喝水 8 杯」）：图标 + 名称 + 进度 `3/8` + 「+1」按钮，点击 +1 并更新进度
- 已完成的习惯显示绿色勾 + 轻灰背景
- 底部「查看全部」→ 跳转我的页

### 3.7 最新日志摘要
- 如果今天写了日志，显示心情标签 + 内容前两行
- 点击 → 跳转日志详情
- 如果今天没写日志，显示轻量引导「记录今天的心情」

### 3.8 空状态
- 当天无任何记录时，显示引导插图 + 「拍照记录第一餐」文字

## 四、饮食页（Food Timeline）

### 4.1 日期导航
- 顶部日期切换，与首页联动
- 左右箭头切换天

### 4.2 餐次时间线
- 按时间顺序排列所有餐食卡片
- 餐次类型：早餐 / 午餐 / 晚餐 / 加餐
- 同一餐次可有多个 Meal 实例（如上午加餐和下午加餐各一张卡片）
- 每一餐为一张卡片

### 4.3 餐食卡片
- 顶部：餐次标签 + 具体时间（如「加餐 · 15:30」）+ 该餐总热量。时间用于区分同餐次的多个 Meal
- 照片区（如有）：AI 拍照记录的原图缩略图，圆角矩形
- **食物明细列表（默认展开）**：
  - 每个 FoodItem 一行：名称 + 份量（如「200g」）+ 热量
  - 点击某个 FoodItem → 弹出编辑 Sheet（可修改名称、份量、营养素）
  - 超过 5 个食物后折叠，显示「还有 N 项」可展开
- 底部：「添加食物」按钮

### 4.4 手动添加食物
- 入口 1：餐食卡片底部「添加食物」
- 入口 2：空餐食卡片上的「记录早餐/午餐/...」
- 弹出 Sheet：
  - 食物名称输入（搜索顺序：我的食物 → 最近使用）
  - 份量 + 单位（g / ml / 份 / 个 / 杯 / 碗 / 片 / 块）
  - 如果单位不是 g/ml：额外输入「1份 = ?g」（必填，用于营养素换算）
  - 热量（匹配我的食物时自动按份量换算填充，可手动覆盖）
  - 三大宏量素（匹配时自动填充，可手动覆盖）
  - 扩展营养素（纤维/钠/糖/胆固醇，可选填）
  - 「收藏到我的食物」开关（首次使用的自定义食物默认开启）
  - 保存按钮

### 4.4b 我的食物
- 用户手动创建或从历史记录中收藏的食物，存为 `UserFood`
- 在手动添加食物的搜索中优先展示
- 按使用频次和最近使用时间排序
- 管理入口：设置页 → 我的食物库
- 每条 UserFood 存储：名称、默认份量、单位、默认份量对应克数、每 100g 营养数据
- 用户可编辑和删除自定义食物

### 4.4c 餐食模板
- 用户可将已记录的一餐保存为模板（如「日常早餐」= 燕麦 + 牛奶 + 蓝莓）
- 从模板创建餐食时，Meal.date 默认为当前时间，用户可在确认前修改份量和时间
- 模板管理入口：饮食页顶部「从模板创建」按钮
- 按使用频次和最近使用时间排序

### 4.5 手动添加餐食
- 饮食页底部「+ 添加一餐」按钮
- 选择餐次（早餐/午餐/晚餐/加餐）
- 选择后立即创建空 Meal 对象，进入添加食物流程
- 如果用户取消（dismiss）且 Meal 下没有任何 FoodItem，自动删除空 Meal

### 4.6 编辑与删除
- 餐食卡片长按或滑动：删除整餐（需确认）
- 食物行滑动：删除单个食物
- 食物行点击：编辑营养数据

### 4.7 每日营养汇总
- 饮食页底部固定栏：今日总热量 / 目标热量（与首页英雄卡片同步）
- 轻量展示，不重复完整营养素列表

### 4.8 搜索与筛选
- 顶部搜索栏：按食物名称搜索（跨所有日期，匹配 FoodItem.name）。SwiftData 底层是 SQLite，`name CONTAINS` 查询在万级数据量上仍为毫秒级，无需额外索引或范围限制
- 搜索结果按日期降序展示，每条显示：日期 + 餐次 + 食物名称 + 份量 + 热量
- 点击搜索结果 → 跳转到该天饮食页并高亮对应餐食卡片
- 筛选选项（可选，V1.0 可简化为仅搜索）：
  - 按餐次筛选（早餐/午餐/晚餐/加餐）
  - 按来源筛选（手动/AI文字/AI拍照）

### 4.9 空状态
- 当天无餐食记录时，显示引导插图 + 「拍照记录第一餐」和「手动添加」两个按钮
- 不预渲染四张固定空卡片（因为餐次数量不固定，用户可能一天只吃两顿）

## 五、AI 聊天模块

### 5.1 入口位置
- 独立 Tab，位于底部导航栏正中央
- AI Tab 按钮视觉突出（与 1Cash 一致）
- 点击后进入全屏独立聊天界面

### 5.2 聊天界面
- 气泡对话样式（用户右侧，AI 左侧）
- AI 消息支持流式输出
- 顶部显示当前服务商图标 + 名称
- 顶部右侧「清空对话」按钮
- 聊天历史跨会话持久化（SwiftData 存储）

### 5.3 拍照识别入口
- 输入框左侧相机图标按钮
- 点击后弹出选项：「拍照」/「从相册选择」
- 「拍照」使用 `UIImagePickerController(.camera)`，第一次点击时触发系统相机权限请求。权限被拒绝后显示引导卡片 + 「去系统设置」按钮
- 「从相册选择」使用 `PhotosPicker`（SwiftUI 原生），不需要显式权限请求
- 照片选择后：
  1. 照片以用户消息气泡形式展示（缩略图）
  2. 同时发送给 AI 服务商 Vision API
  3. AI 返回识别结果，展示为结构化餐食确认卡片（支持 `add_meal` 单餐和 `add_meals` 多餐）

### 5.4 照片处理流程
- 拍照 / 选图后，先压缩至 1MB 以内（保持可辨识的食物细节）
- 生成 200px 缩略图用于列表展示
- 原图压缩后存入 Meal.photoData
- 缩略图存入 Meal.photoThumbnail
- 发送给 AI 时使用压缩后的图片数据

### 5.5 AI 结构化意图

| 意图 | 功能 | 参数 |
|------|------|------|
| `add_meal` | 记录一餐（文本描述） | mealType, items[{name, amount, unit, calories, protein, carbs, fat, fiber, sodium, sugar, cholesterol}], note |
| `recognize_meal_photo` | 拍照识别一餐（图片通过 AIVisionRequest 发送，不在 JSON 中） | mealType, items[...同上] |
| `add_journal` | 记录日志 | content, mood, tags[] |
| `add_habit_log` | 记录习惯完成 | habitName, value |
| `get_today_nutrition` | 查询今日营养摘要 | 无 |
| `get_nutrition_analysis` | 营养分析（如「我这周蛋白质够吗」） | dateRange |
| `get_meal_history` | 查询饮食记录 | date, mealType |
| `add_meals` | 一次记录多餐（如「早上吃了面包，中午吃了盖浇饭」） | meals[{mealType, items[], note}] |
| `add_water` | 记录饮水 | amount(ml) |
| `use_meal_template` | 从模板创建餐食 | templateName, mealType |

### 5.5b AI 返回 JSON 格式示例

文字记录示例（用户说「午饭吃了一碗米饭、一块鸡胸肉和炒西兰花」）：
```json
{
  "intent": "add_meal",
  "meal_type": "lunch",
  "items": [
    {"name": "米饭", "amount": 1, "unit": "碗", "calories": 232, "protein": 4.6, "carbs": 51.5, "fat": 0.6},
    {"name": "鸡胸肉", "amount": 1, "unit": "块", "calories": 165, "protein": 31, "carbs": 0, "fat": 3.6},
    {"name": "炒西兰花", "amount": 1, "unit": "份", "calories": 65, "protein": 4.3, "carbs": 5.2, "fat": 3.1}
  ],
  "note": ""
}
```

拍照识别示例（AI 返回格式相同，intent 不同）：
```json
{
  "intent": "recognize_meal_photo",
  "meal_type": "lunch",
  "items": [
    {"name": "番茄炒蛋", "amount": 1, "unit": "份", "calories": 180, "protein": 10, "carbs": 8, "fat": 12},
    {"name": "米饭", "amount": 1, "unit": "碗", "calories": 232, "protein": 4.6, "carbs": 51.5, "fat": 0.6}
  ],
  "note": ""
}
```

多餐记录示例（用户说「早上吃了面包牛奶，中午吃了盖浇饭」）：
```json
{
  "intent": "add_meals",
  "meals": [
    {
      "meal_type": "breakfast",
      "items": [
        {"name": "面包", "amount": 2, "unit": "片", "calories": 160, "protein": 5, "carbs": 30, "fat": 2.5},
        {"name": "牛奶", "amount": 250, "unit": "ml", "calories": 162, "protein": 8, "carbs": 12, "fat": 8}
      ],
      "note": ""
    },
    {
      "meal_type": "lunch",
      "items": [
        {"name": "盖浇饭", "amount": 1, "unit": "份", "calories": 580, "protein": 18, "carbs": 75, "fat": 22}
      ],
      "note": ""
    }
  ]
}
```
确认卡片显示两张（早餐卡 + 午餐卡），用户可分别编辑和确认。

非记录意图示例（用户说「我今天蛋白质够了吗」）：
```json
{
  "intent": "chat",
  "response": "你今天已摄入蛋白质 62g，目标 100g，还差 38g。建议晚餐补充一份鸡胸肉或鱼肉。"
}
```

**字段规则**：
- `items[].calories` 是该份量的实际热量（不是 per 100g）
- `items[].protein/carbs/fat` 可省略，省略时解码为 nil
- `items[].fiber/sodium/sugar/cholesterol` 文字记录时不要求 AI 返回（减少 token），拍照识别时可选返回
- `meal_type` 如果 AI 无法判断，返回 `"snack"`（加餐）作为兜底
- `note` 可为空字符串
- 无法解析为结构化意图时，返回 `{"intent": "chat", "response": "..."}`

### 5.6 AI 餐食确认卡片
- 当 AI 从文字或照片解析出餐食后，返回结构化卡片：
  - 照片缩略图（如有）
  - 餐次 + 总热量
  - 食物列表：每行显示名称 + 份量 + 热量 + 蛋白质/碳水/脂肪迷你标签
  - 每行可点击编辑
  - 底部「+ 添加遗漏的食物」按钮（点击后弹出手动添加 Sheet，添加的 FoodItem 追加到卡片列表中）
  - 「确认记录」+「取消」按钮
- 确认后：Meal + FoodItem 写入 SwiftData，标记 `source = .aiPhoto` 或 `.aiText`
- 确认后卡片变为已记录状态，显示「已记录」+ 撤销按钮
- **撤销有效期**：确认后 24 小时内显示「撤销」按钮。超过 24 小时后，按钮变为「删除记录」并走正常删除确认流程（弹窗确认）。避免用户误点一个月前的撤销按钮删掉旧数据。
- 如果用户后续在饮食页删除了该餐食，聊天历史中的卡片自动变为「该记录已删除」灰色状态，撤销/删除按钮隐藏

**Streak 计算规则**：
- **每天型**（如「每天冥想」）：连续完成的自然天数。昨天未完成则 Streak 归零。
- **每周 N 次型**（如「每周跑步 3 次」）：连续完成的自然周数。自然周定义为周一至周日。某周完成次数 ≥ N 则该周算完成，否则 Streak 归零。周中时不判断当前周（因为还有机会完成），只判断已过的完整周。
- **自定义频率**：按用户定义的周期和次数，逻辑同每周型。

- 不再追踪的习惯可归档而非删除

### 6.3 日志

## 八、营养目标管理

### 8.1 目标计算逻辑

如果用户提供了身体参数（性别、年龄、身高、体重、活动水平），使用 Mifflin-St Jeor 公式计算个性化目标：

```
男性 BMR = 10 × 体重(kg) + 6.25 × 身高(cm) - 5 × 年龄 + 5
女性 BMR = 10 × 体重(kg) + 6.25 × 身高(cm) - 5 × 年龄 - 161
TDEE = BMR × 活动系数（久坐 1.2 / 轻度 1.375 / 中度 1.55 / 重度 1.725）
```

| 模式 | 热量 | 蛋白质 | 碳水 | 脂肪 |
|------|------|--------|------|------|
| 减脂 | TDEE × 0.80 | 30% 热量 | 40% 热量 | 30% 热量 |
| 增肌 | TDEE × 1.15 | 30% 热量 | 50% 热量 | 20% 热量 |
| 维持 | TDEE × 1.00 | 20% 热量 | 55% 热量 | 25% 热量 |
| 均衡 | TDEE × 1.00 | 15% 热量 | 60% 热量 | 25% 热量 |

如果用户跳过了身体参数，使用通用默认 TDEE = 2,000 kcal。

**示例**：25岁女性，165cm，58kg，轻度活动，选择减脂：
- BMR = 10×58 + 6.25×165 - 5×25 - 161 = 1,327 kcal
- TDEE = 1,327 × 1.375 = 1,824 kcal
- 减脂热量 = 1,824 × 0.8 = **1,459 kcal**（而非固定的 1,600 kcal）

用户可自由覆盖任意字段。覆盖后的值不会被模式切换自动替换（除非用户主动选择「恢复推荐值」）。

### 8.2 扩展营养素默认目标

| 营养素 | 每日推荐值 | 来源 |
|--------|-----------|------|
| 膳食纤维 | 25g | 中国居民膳食指南 |
| 钠 | ≤2,000mg | WHO 建议 |
| 糖 | ≤50g | WHO 建议 |
| 胆固醇 | ≤300mg | 中国居民膳食指南 |

### 8.3 目标调整规则
- 切换饮食目标模式时，弹窗询问「是否同时恢复该模式的推荐营养目标？」
- 用户手动修改过的值不会被模式切换自动覆盖（除非用户选择恢复）

## 九、用户食物、模板库与饮品知识库

### 9.1 设计目标
- 新安装的空 App 不内置家常菜、品牌食品或官方饮品营养记录。
- 用户可以手动创建我的食物，或从已记录餐食保存为模板。
- 饮品营养识别插件可从图片/文字提取饮品数据，用户校对后写入饮品知识库。
- AIChat 优先复用用户创建的本地数据；未命中时才使用 AI 估算，并在确认卡片中展示来源和置信度。

### 9.2 数据结构
- `UserFood`：名称、默认份量、单位、默认份量对应克数、每 100g 营养数据、使用次数、最近使用时间。
- `MealTemplate`：模板名称、餐次、食物条目快照 JSON、使用次数、最近使用时间。
- `DrinkRecord`：品牌、饮品名、规格、糖度/冰量/小料、热量、宏量营养素、来源备注和置信度。

### 9.3 匹配逻辑
- 手动添加食物：搜索我的食物和最近记录；未命中时用户手动输入营养数据。
- AIChat 模板复用：用户明确提到模板库/模板时，匹配用户创建的 MealTemplate。
- AIChat 饮品记录：奶茶、咖啡、果茶等文本优先匹配用户校对过的 DrinkRecord，并按甜度/冰量策略调整。
- 空库状态下不会命中本地营养数据，AI 输出必须标注为估算或用户提供标签换算。

## V1.0 范围与 Coming Soon

### V1.0 包含（首发功能）
- 完整 Onboarding 流程（含身体参数、饮食目标、AI 配置）
- 首页今日仪表盘（英雄卡、营养素列表、三餐摘要、动态 TDEE/活动消耗、饮水、习惯、日志）
- 饮食记录（手动添加食物、手动添加餐食、编辑、删除）
- AI 文字记录（本地解析 + 远程 AI）
- AI 拍照识别（多模态）
- 用户自建食物、模板库与饮品知识库
- 我的食物 + 餐食模板
- Apple Health 动态 TDEE 与训练摘要（读取活动热量、静息热量、步数、训练记录、身高体重，用于目标估算和训练汇总）
- 水分追踪
- 运动/健康习惯追踪（创建、打卡、Streak、归档）
- 日志（写、读、搜索、筛选，用于状态和训练复盘）
- 设置全套
- 数据导出（CSV + JSON）
- 测试套件

### Coming Soon（V1.0 中使用家族 Coming Soon 模式预览）
- **营养趋势报告**：首页或饮食页展示 blur 预览 + 「Coming Soon」标签，列出功能点（周报、月报、营养素趋势图、饮食模式分析）
- **运动健身报告**：活动消耗、训练习惯、饮食目标达成和体重趋势的联合分析
- **AI 营养分析**：AI Tab 中的 `get_nutrition_analysis` 意图在 V1.0 返回基础文字回复，深度图表分析为 Coming Soon
- **iCloud 同步**：设置页禁用状态 + 「即将推出」
- **习惯洞察**：热力图在 V1.0 实现，但更深度的统计分析（如「什么时候最容易坚持/放弃」）为 Coming Soon

### 不在规划中（不做 Coming Soon 预览）
- 社交功能（分享饮食、好友排行）
- 食谱推荐
- 条形码扫描
- 与健康类硬件（体重秤、手环）的连接
