# 1Life — 设计自述

> 写给 UI 设计师的产品灵魂描述
> 版本：1.0 | 2026-06-25
> 代码库归档：本文件随 `1Life` 仓库维护，用于约束产品气质、视觉语言和后续界面迭代方向。

---

## 一、这是一个什么产品

**1Life** 是一款以营养健康与运动健身为核心的个人健康管理 App。名字里的「1」代表一目了然——用户打开它，就能在一秒钟内看清自己今天摄入了多少热量、消耗了多少活动能量、离营养目标和训练状态还差多远。

它不是专业运动员的营养计算器，不是医院的膳食处方系统，也不是只记录步数的运动打卡器。它做的是：让记录饮食变得极其简单，让了解自己的营养状况和运动消耗变得极其清晰。AI 拍照识别让用户对着一盘菜拍一张照片，就能自动获得热量和营养信息；Apple Health 和身体参数让 App 能把摄入与 TDEE、活动热量、减脂/增肌目标联系起来。

它的竞争对手不是 MyFitnessPal 那样的专业健身工具，也不是单纯的运动手环面板，而是用户脑子里模糊的「我今天好像吃得还行、练得也还可以」。1Life 要做的，是把那团模糊变成一组清晰的数字：摄入、消耗、蛋白质、碳水、脂肪、饮水和身体状态，让用户从猜测变成了解。

除了营养健康与运动健身，它还承载日常日志和习惯追踪——但这两个是辅助角色。营养、热量目标、活动消耗和训练相关状态是舞台中央的主角；日志用于记录心情、压力、睡眠和身体感受，习惯用于轻量追踪喝水、拉伸、训练、早睡等行为。

它服务的用户：关注健康、在乎饮食、正在减脂/增肌/维持体型、但不想把吃饭和训练变成一门功课的人。他们可能是想减脂的上班族，可能是健身爱好者，可能是刚开始运动的人，也可能是想给全家吃得更健康的家长。他们的共同特征是：希望了解自己吃了什么、消耗了多少、训练和营养是否匹配，但不希望为了「了解」付出太大代价。

## 二、产品的性格

如果 1Life 是一个人，他是什么样的？

**温暖、清晰、不说教。** 他不会对你喊「你今天脂肪超标了！」，他会平静地告诉你「今日脂肪摄入 78g，目标 65g，主要来自午餐的红烧肉」。他不评判你的食物选择，只呈现事实和营养拆解。他像一个了解营养学的朋友，在你问他之前，他已经把每一餐的营养素算好了。

他不花哨。他不会用十种颜色画一张营养素雷达图来炫技，他只会在你真正需要关注的地方用颜色说话——比如你的蛋白质摄入连续三天不足，进度条才会变成警示色。

他有科技感，但不冷漠。AI 拍照识别让他能看懂你的餐盘，但他的回应不像实验室报告——「午餐已记录：米饭 230kcal + 清炒西兰花 45kcal + 煎鸡胸肉 165kcal，共 440kcal」，这句话读起来应该像一个贴心的营养助手，而不是数据库查询结果。

他和 1Cash 是兄弟。1Cash 掌管你的钱包，1Life 掌管你的餐盘、能量消耗和训练状态。两个人穿一样风格的衣服，说一样节奏的话，只是关心的领域不同。

## 三、整体设计语言

### 白色是主角，不是底色

与 1Cash 一致，1Life 的背景是白色。白色让营养数字和食物信息浮现出来，让用户的视线自然落在最重要的内容上——那个代表「今日摄入热量」的大数字。

留白是呼吸，不是空洞。卡片之间的间距、食物条目之间的行距，都应该让人感觉从容，而不是被密密麻麻的营养表格压迫。

### 数字是英雄

这是一款营养追踪 App，数字就是产品的主角。热量数字用**圆润的等宽数字字体**（SF Rounded），大、清晰、有重量感。1,240 kcal 这几个字，应该是首页上最有存在感的元素。

数字字体的层级：
- 首页核心热量数字：最大（40-46pt），最重（Bold/Black）
- 宏量素数字（蛋白质/碳水/脂肪）：中等（18-20pt），半粗
- 食物条目热量：正文大小（15pt），Medium
- 辅助营养素数字（纤维/钠/糖等）：小字（13pt），Regular，次级灰色

### 卡片是容器

页面的组织单位是**卡片**。与 1Cash 一致：

- 圆角：16-20pt
- 背景：`secondarySystemBackground`
- 阴影：极轻微或无
- 内边距：水平 20pt，垂直 20pt

每个页面 3-5 张卡片是上限。一餐的食物明细卡片内部可以有多行，但整体仍然是一张卡片，不是散落的行。

### 颜色的使用原则

颜色是意义的载体，不是装饰。与 1Cash 一致：

- **主色调**：待定，建议单色系
- **语义色**：
  - 红色系：超标、警告、删除
  - 绿色 / Teal 系：达标、正向状态、习惯完成
  - 蓝色系：进行中、一般强调
  - 橙色系：接近上限、注意
  - 灰色系：辅助信息、禁用态
- **营养素颜色**：三大宏量素各有固定色（如蛋白质蓝、碳水橙、脂肪黄），贯穿全 App。这三个颜色在进度条、环形图、食物明细中保持一致。
- **单页面颜色上限**：有颜色的元素不超过 3 种颜色（营养素三色作为一组算一种）。

### 食物照片的展示

食物照片是 1Life 独有的视觉元素（1Cash 和 1Track 没有）。

- 照片以圆角矩形裁切（12pt 圆角），嵌在餐食卡片内
- 照片尺寸在卡片内不超过卡片宽度的 40%，靠左或靠上
- 没有照片的餐食用餐次图标（早餐/午餐/晚餐/加餐的 SF Symbol）替代
- 照片不是装饰，是记录的一部分——如果用户通过 AI 拍照记录了一餐，照片应该出现在这一餐的卡片里

## 四、各页面的视觉叙事

### 首页（Today Dashboard）

**这个页面要传递的感觉：今天摄入、消耗和健康状态怎么样，一眼就知道。**

用户打开 App 的第一眼，应该立刻看到「今天摄入了多少热量」以及它和目标/TDEE 的关系——这是首页的灵魂，也是最大的那个数字。对于开启 Apple Health 的用户，活动热量和动态 TDEE 应该成为同一张健康账本的一部分。

视觉层级从上到下：
1. 日期导航（轻量，不抢眼）
2. **英雄卡片**——热量大数字 `1,240 / 2,000 kcal` + 圆形进度环 + 三大宏量素进度条
3. 营养素详细列表（**默认折叠**，点击「查看全部营养素 ▾」展开。英雄卡已有三大宏量素，展开留给需要细节的用户。减少首页默认高度）
4. 三餐摘要条（紧凑一行：早餐 320kcal · 午餐 540kcal · 晚餐 — · 加餐 180kcal，只显示热量数字，不展开食物明细——明细是饮食页的职责）
5. 活动消耗 / 动态 TDEE 摘要（开启 Apple Health 时显示，未开启时弱提示）
6. 饮水进度条（水滴图标 + `1,250 / 2,000 ml` + 「+1杯」快捷按钮）
7. 习惯完成度卡片（今日 3/5 完成，可直接打勾，运动/拉伸/训练类习惯优先露出）
8. 最新日志摘要（如果今天写了日志，显示开头几行）

**首页与饮食页/我的页的边界**：首页是"一眼看全天"——每个维度（热量、餐食、活动消耗、饮水、运动/习惯、日志）各占一个紧凑卡片。饮食页是"看清每一口"——完整的餐食卡片、食物明细、营养拆解。我的页承载运动/习惯和日志的完整历史。三者信息不重叠。

**英雄卡片**是整个 App 设计的精华。热量大数字应该大到让人第一眼就能读出来。数字旁边或上方是一个圆形进度环，填充程度代表今日热量占目标的比例。进度环下方是三条宏量素进度条（蛋白质 / 碳水 / 脂肪），每条用对应的固定颜色，显示 `当前g / 目标g`。

进度环颜色逻辑：
- 0-80%：主色（平静）
- 80-100%：橙色（接近目标）
- 100%+：红色（超标）
- **「均衡饮食」模式例外**：进度环全程使用主色，不变橙也不变红（因为不是严格目标）。目标数字旁标注「参考」二字，暗示这只是参考值而非硬上限。

**营养素详细列表**在英雄卡片下方，默认展开。列出所有追踪的营养素，每行：名称 + 当前值 + 目标值 + 迷你进度条。保持克制，不要用图表，进度条就够了。

### 饮食页（Food Timeline）

**这个页面要传递的感觉：今天的每一餐，清清楚楚。**

按时间顺序排列的餐食卡片列表。每一餐是一张卡片，卡片内：

- 顶部：餐次标签（早餐 / 午餐 / 晚餐 / 加餐）+ 该餐总热量 + 记录时间
- 照片（如有，AI 拍照记录的原图缩略图）
- **食物明细列表（默认展开）**：每个 FoodItem 一行，显示名称 + 份量 + 热量。这里不需要显示完整营养素，热量数字就够了。
- 底部：「手动添加食物」按钮

同一餐次可以有多张卡片——下午加餐和睡前加餐各一张，不需要挤在同一个"加餐"卡片里。

卡片的展开/收起不是交互重点。默认展开，让用户扫视就能看到每一餐吃了什么。如果一餐有 8 个以上食物，超过 5 个后折叠，显示「还有 3 项」。

**顶部操作栏**：日期导航（左右箭头切换天）+ 「从模板创建」按钮。模板让用户一键复用常吃的餐食组合（如每天相同的早餐），不需要每次重新输入。

**空状态**：当天无任何餐食时，显示引导插图 + 「拍照记录」和「手动添加」两个按钮。不预渲染固定数量的空卡片，因为用户的餐次数量不固定。

### AI 聊天（AI Chat — 独立全屏 Tab）

**这个页面要传递的感觉：在跟一个懂营养的朋友说话，还能拍照给他看。**

与 1Cash 的 AI 聊天保持高度一致的骨架，但增加拍照能力：

- 气泡对话样式（用户右侧，AI 左侧）
- AI 消息支持流式输出
- 顶部显示当前服务商图标 + 名称
- 顶部右侧「清空对话」按钮
- 聊天历史跨会话持久化

**拍照入口**：输入框左侧增加一个相机图标按钮。点击后可选「拍照」或「从相册选择」。照片发送后，以用户消息气泡的形式展示缩略图，AI 返回识别结果。

**AI 餐食识别结果卡片**——这是 1Life AI 模块最核心的设计元素：

当 AI 从照片或文字中识别出一餐食物后，返回一张**结构化餐食卡片**：
- 顶部：餐次 + 总热量
- 食物列表：每个食物一行（名称 + 份量 + 热量 + 蛋白质/碳水/脂肪迷你标签）
- 每个食物行可点击编辑份量和营养数据
- 底部：「确认记录」+「取消」按钮
- 如有照片：卡片顶部显示原图缩略图

这张卡片是 1Life 的「信任时刻」——用户拍了一张午餐的照片，AI 告诉他每样菜是什么、有多少热量。如果这张卡片清晰、准确、可编辑，用户就会信任这个功能。

**快捷建议 Chip**：
- 「记录早餐」
- 「拍照识别」
- 「今天吃了什么」
- 「营养分析」
- 「记录喝水」

### 我的页（My Life）

**这个页面要传递的感觉：我的日常，有条不紊。**

上下分区布局，不使用 Segmented Control——习惯打卡是高频动作（一天点很多次），日志是低频写作（一天最多一次），两者交互节奏完全不同，用 Segmented Control 切换会给高频打卡增加不必要的摩擦。

**习惯追踪区（上半部分，约 40%）**：
- 今日习惯紧凑网格（每个习惯一张小卡片：图标 + 名称 + 进度 + 完成按钮）
- 连续天数（Streak）展示
- 「管理习惯」入口
- 全部完成后可折叠，留更多空间给日志

**日志区（下半部分）**：
- 时间线列表，按天分组
- 每条日志：日期 + 心情标签 + 内容摘要（两行截断）
- 点击进入日志详情/编辑
- 右下角浮动「写日志」按钮

**首页习惯卡片 vs 我的页习惯区的分工**：首页的习惯卡片用于快速打卡（点一下就完成），我的页的习惯区提供完整管理能力（查看详情、历史热力图、编辑、归档）。

设计原则：这个页面不需要英雄卡片，不需要大数字。它是安静的、个人的、随手记的。视觉节奏比首页和饮食页更松散。

### 设置页（Settings）

**与 1Cash 设置页保持高度一致的结构。**

分组列表（`.insetGrouped`），从上到下：
1. 个人资料（头像 + 昵称）
2. 营养目标（每日热量、蛋白质、碳水、脂肪等目标值）
3. 饮食偏好（饮食目标：减脂/增肌/维持/均衡）
4. 提醒设置（三餐提醒时间）
5. AI 配置（服务商 + API Key + 模型选择 + 测试连接）
6. 数据（导出 / 导入 / 清空）
7. 隐私政策 / 用户手册 / 反馈
8. 版本号

### 底部导航栏（Tab Bar）

与 1Cash 完全一致的设计语言：

**Tab 排列（左→右）：** 今日 | 饮食 | **AI（中央）** | 我的 | 设置

**AI 中央按钮**：图标外套圆形色块背景，尺寸比普通 Tab 大 20-30%。点击时有轻触觉反馈。

其余 4 个 Tab 使用标准 SF Symbol + 文字标签，选中态填色，未选中态灰色。

## 五、动效哲学

与 1Cash 一致：**动效是确认，不是表演。**

| 场景 | 动效方式 | 时长 |
|------|---------|------|
| 热量数字变化 | 数字滚动（countingAnimation） | 0.4s |
| 营养素进度条出现 | 从左向右生长 | 0.5s, spring |
| 餐食记录成功（手动保存 / AI 确认） | 绿色成功覆层（对齐 1Cash） | 0.8s |
| AI 消息出现 | 从下方滑入 + 淡入 | 0.25s |
| AI 流式输出 | 逐字显示 | 实时 |
| 习惯完成打勾 | 勾选动画 + 轻触觉反馈 | 0.3s |
| Tab 切换 | 无动效，即时切换 | — |
| 照片拍摄后 | 缩略图从底部滑入气泡 | 0.3s |
| 弹出 Sheet | 系统默认 bottom sheet | — |
| 食物明细展开/收起 | 高度动画 | 0.25s |

**不要做的动效：**
- 页面之间的自定义转场
- 营养素雷达图旋转出现
- 任何超过 0.5 秒的纯装饰动效
- 食物照片的滤镜或特效

## 六、图标风格

与 1Cash 一致，所有功能图标使用 **SF Symbols**。

餐次图标建议：
- 早餐：`sunrise.fill`
- 午餐：`sun.max.fill`
- 晚餐：`moon.fill`
- 加餐：`cup.and.saucer.fill`

习惯图标由用户从预设库中选择，视觉重量统一，使用 fill 变体。

## 七、Onboarding 设计方向

与 1Cash 的 Onboarding 保持相同的骨架节奏。每个步骤只做一件事，页面中心有大图或大标题。

**步骤：**
1. 欢迎页（App Logo + Slogan）
2. 语言选择
3. 个人资料（头像 + 昵称）
4. 身体参数（性别、年龄、身高、体重、活动水平 — 可跳过）
5. 饮食目标（减脂 / 增肌 / 维持 / 均衡）— 这一步决定默认营养目标
6. 每日热量目标（根据身体参数 + 饮食目标个性化推荐，可手动调整）
7. 提醒节奏（三餐提醒时间选择）
8. AI 配置（可跳过）
9. 设置完成（摘要 + 进入 App）

**身体参数页**是 Onboarding 中最影响后续体验的一页。参数用于 Mifflin-St Jeor 公式计算基础代谢率，为热量目标提供科学基准。设计上不要让用户觉得是在填体检表——用大号数字输入，每个参数占一行，轻量友好。跳过按钮要明显，不强迫填写。

**饮食目标选择页**是 Onboarding 里最有视觉表现力的一页。每个目标以卡片展示，如果上一步填写了身体参数，卡片中的热量推荐值是个性化计算的结果（如「减脂：1,459 kcal/天」），而非通用数字。

## 八、深色模式

与 1Cash 一致，完整支持深色模式：
- 所有颜色使用语义色，自动适配
- 卡片背景用 `secondarySystemBackground`
- 营养素三色（蛋白质/碳水/脂肪）在深色模式下适当提亮
- 食物照片不做处理，保持原色

---

## 九、设计禁忌

**不要做这些事：**

- 不要同一页面使用超过 3 种颜色（营养素三色组算一种）
- 不要用雷达图、蛛网图展示营养素（进度条更清晰）
- 不要在列表页放超过 6 个筛选项
- 不要弹窗里嵌套弹窗
- 不要让用户为了记录一餐点超过 4 次（拍照 → 确认 → 保存，3 次以内）
- 不要用小于 13pt 的字体显示任何有意义的信息
- 不要在一个页面里同时出现超过 2 个主操作按钮
- 不要把食物照片做成 Instagram 风格的滤镜效果
- 不要对食物选择做道德判断——不标记食物为「不健康」「垃圾食品」，不在食物旁放红色 X 或警告图标。颜色变化只用于**数字与目标的对比**（超标变红是在说「你今天的总量超过了你自己设的目标」，而不是在说「你不应该吃这个」），永远不要把颜色直接加在食物名称或食物照片上
- 不要动效超过 0.5 秒
- 不要在深色模式下写死白色或黑色

## 十、一句话设计方向

> 让每一餐都被看见，让每一口都有数字，让每一天都更了解自己。
