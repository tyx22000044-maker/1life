# 1Life UI Style Guide V2

> 基于 2026-06-30 提供的新版视觉参考图整理
> 最后更新：2026-06-30
> 本文是 `1App Family` 共享 UI V2 规范在 `1Life` 中的落地说明，不是独立设计体系。
> 总规范见：`APP_FAMILY_CONTEXT.md`

---

## 1. Design Direction

### 1.0 Family Inheritance

`1Life` 的这套新 UI 不是单独成立的一套视觉系统，而是整个 `1App Family` 的共享升级方向。

这意味着：

- `AI Chat` 必须与其他家族 App 保持高度一致
- `Settings` 必须与其他家族 App 保持高度一致
- `AI Configuration` 必须与其他家族 App 保持高度一致
- 通用头部、状态标签、面板容器、记录行应尽量复用相同语法

`1Life` 在本文件中主要记录的是：

- 家族共享规范在健康场景中的应用方式
- `1Life` 特有页面的内容结构
- `1Life` 特有颜色语义，如营养素与饮水

新版 `1Life` 不再强调“健康 App 的柔和陪伴感”，而是强调：

- 像一套个人健康操作系统
- 像一个清晰、可信、可校验的数据面板
- 像把饮食、运动、身体参数和习惯记录统一进同一套控制台

一句话总结：

**Medical-lite 的理性秩序 + Ledger/Terminal 风格的信息结构 + iOS 原生可用性。**

这套风格与 `1Cash` 新参考图同源，但在 `1Life` 中应保留健康场景应有的可读性，不能为了“硬朗”牺牲理解效率。

## 2. Core Visual DNA

### 2.1 Temperament Keywords

- Systematic
- Precise
- Restrained
- Modular
- Monochrome-first
- Data-forward
- Functional

### 2.2 What It Should Feel Like

- 用户看到页面时，首先感到“结构清楚”
- 用户读到数字时，感到“可信、稳定、可比较”
- 用户切换 Tab 或打开设置时，感到“像在浏览一套统一系统”

### 2.3 What To Avoid

- 过度生活方式化的插画感
- 大面积柔和渐变
- 糖水感按钮
- 过多圆角和胶囊
- 漂浮感太强的阴影卡片
- 信息块之间边界模糊
- 为了“健康”而滥用绿色

---

## 3. Layout Principles

### 3.1 Grid First

界面优先依赖网格和分区，而不是依赖颜色制造层级。

- 模块必须有清晰边界
- 同级模块使用统一宽度、统一内边距
- 信息应尽量沿左边线或基线对齐
- 列表项优先做成“记录行”或“系统条目”，而非松散卡片

### 3.2 Sectioned Surface

页面中的每块内容都应该像一个功能面板：

- 有明确边框或明确容器边界
- 有面板标题或分组标签
- 有稳定的内部节奏

优先顺序：

1. 描边分区
2. 极浅底色分区
3. 少量状态色强调

### 3.3 Density

信息密度应高于当前 V1 风格，但不能拥挤。

- 页面外边距：16pt
- 面板间距：12pt
- 面板内边距：16pt
- 紧凑信息组内部间距：6-8pt
- 常规信息组内部间距：10-12pt

## 4. Color System

### 4.1 Palette Strategy

整体采用 **黑 / 白 / 灰 + 少量状态色**。

基础原则：

- 黑色负责结构和核心信息
- 灰色负责层级和辅助信息
- 白色负责留白和呼吸
- 彩色只负责“状态”

### 4.2 Base Colors

建议在 SwiftUI 中优先映射为系统语义色，必要时再补自定义值。

| 用途 | 建议表现 |
|------|----------|
| 页面背景 | 接近纸白的浅灰白 |
| 面板背景 | 白色或极浅暖灰 |
| 主文本 | 近黑 |
| 次文本 | 中灰 |
| 边框/分割线 | 浅灰偏深 |
| 强反差区域 | 纯黑或近黑 |

### 4.3 Accent / State Colors

| 语义 | 建议颜色方向 | 用法 |
|------|--------------|------|
| 主要数值联动 | 蓝色 | 热量、动态状态、关键数值 |
| 警告/异常 | 红色 | 超标、缺失、未配置 |
| 达标/成功 | 深青或低饱和绿色 | 完成、同步成功 |
| 提醒/待处理 | 橙色 | 接近上限、等待确认 |

规则：

- 单屏彩色种类尽量不超过 2 种
- 同一组件中，彩色只点亮最重要的一项
- 不用彩虹式营养图

### 4.4 1Life-Specific Nutrition Mapping

`1Life` 仍然可以保留营养语义色，但要收敛饱和度。

| 营养项 | 建议方向 |
|--------|----------|
| 蛋白质 | 冷蓝 |
| 碳水 | 柔和橙 |
| 脂肪 | 暖灰黄或琥珀 |
| 饮水 | 浅蓝 |

这些颜色只用于：

- 进度条填充
- 极小尺寸标签
- 单项指标高亮

不要用于大面积背景。

## 5. Typography

### 5.1 Typography Character

新版字体表达不应再以“圆润友好”为首要目标，而应强调：

- 高对比
- 明确层级
- 标签化
- 数据可读性

### 5.2 Text Roles

| 层级 | 风格 |
|------|------|
| Hero 数字 | 大、重、稳定，优先等宽数字 |
| 页面主标题 | 全大写或高权重标题 |
| 面板标签 | 小号、加宽字距、偏机械感 |
| 正文 | 简洁清楚，不装饰 |
| 辅助说明 | 小号、紧凑、低对比 |

### 5.3 Recommended Rules

- 大数字优先使用等宽数字特性
- 分组标题可用全大写
- 分组标题字距略放大，形成设备标签感
- 普通正文保持可读，不要全站都做大写
- 描述文案尽量短句、事实导向

### 5.4 Suggested SwiftUI Mapping

- Hero 数字：`32-40pt`，`bold/black`
- 页面大标题：`28-34pt`，`bold/black`
- 分组标签：`11-12pt`，`semibold`，增加 tracking
- 列表主文本：`15-17pt`
- 列表辅文本：`11-13pt`

## 6. Shape Language

### 6.1 Corners

整体从“圆润卡片”收紧到“轻圆角面板”：

- 主面板：10-14pt
- 小按钮：8-10pt
- 小型状态块：6-8pt
- 特殊强调块：可直角或 4-6pt

避免：

- 20pt 以上的大圆角主卡片
- 大量 Capsule 形状

### 6.2 Borders

描边是这套新风格的关键。

建议：

- 面板优先使用 1px 左右浅灰描边
- 重要黑色状态块可用反色处理
- 列表项之间可用细分割线，而不是完全依靠空白

### 6.3 Shadows

- 阴影极弱或不用
- 若使用，仅用于让白色面板与背景轻微分离
- 绝不做“悬浮玻璃卡片”

## 7. Component Rules

### 7.1 App Header

顶部结构应更像“系统栏”：

- 左侧功能入口
- 中间品牌或页面名
- 右侧账户/状态入口

特征：

- 横向对齐严格
- 高度稳定
- 底部可带细分割线

### 7.2 Panel Card

每个卡片应更像信息面板：

- 有外框
- 有明确标题区与内容区
- 内容按照左对齐信息流布局

适用于：

- Dashboard 核心指标
- 营养目标
- AI 识别结果
- 设置分组

### 7.3 Record Row

记录类条目参考参考图中的 Ledger 行：

- 左侧图标或类型标识
- 中间主信息
- 右侧关键数值
- 角落位置放状态 tag

适用于：

- 餐食项
- 饮水记录
- 运动记录
- 习惯完成历史

### 7.4 Search / Filter Controls

搜索框和筛选器不做柔和胶囊，改为系统面板控件：

- 细描边
- 直线边缘
- 图标小而明确
- 文字偏标签感

### 7.5 Status Tag

状态标签应非常克制：

- 尺寸小
- 大写或半大写
- 允许描边或浅色底
- 只在必要时显示

示例语义：

- `SYNCED`
- `PENDING`
- `OVER`
- `UNSET`
- `LOGGED`

### 7.6 Primary Action

主要操作按钮不再追求“饱满蓝色大按钮”的普适方案，而是分两类：

- 系统主操作：黑底白字或深色高反差按钮
- 页面内次操作：白底描边按钮

这样更符合参考图中的设备控制感。

### 7.7 Bottom Navigation

底部导航应具有“设备底栏”的感觉：

- 每个 Tab 像一个均分功能位
- 选中项使用高反差反色块
- 非选中项保持极简线性图标
- 分割线存在感可以略强于当前默认 Tab Bar

### 7.8 Shared Surfaces That Must Stay Aligned

以下界面在 `1Life` 中不应随意做成与其他家族 App 不同的样子：

- `AI Chat`
- `AI Configuration`
- `Settings`
- Profile / Avatar 编辑
- 通用 destructive confirmation

要求：

- 骨架一致
- 节奏一致
- 标题层级一致
- 按钮等级一致
- 分组容器语言一致

允许不同的部分：

- `1Life` 特有的内容项
- 健康领域说明文案
- AI 识别结果中的餐食/营养结构卡片

## 8. Motion Principles

### 8.1 Motion Character

动效要像“切换状态”，不是“玩具反馈”。

- 短
- 准
- 收得快

### 8.2 Recommended Motion

- 面板载入：轻微淡入 + 4-8pt 上移
- Tab 切换：干脆，不拖泥带水
- 列表展开：优先高度变化 + 淡入
- 数值更新：允许微弱过渡，但不做夸张跳动

### 8.3 Avoid

- 弹簧感太强的动画
- 过于柔软的缩放反馈
- 大面积渐变流动

---

## 9. Content Style

### 9.1 Copy Tone

文案要更像系统输出，但不能失去友好度。

建议：

- 少形容词
- 多事实描述
- 多用“当前值 / 目标值 / 状态”
- 少用鼓励式口号

例子：

- 好：`今日摄入 1420 kcal`
- 好：`蛋白质低于目标 18g`
- 好：`健康数据未同步`
- 少用：`继续加油，今天也很棒`

### 9.2 Label Style

适合增加系统感的标签：

- `TODAY`
- `MEALS`
- `BODY`
- `GOALS`
- `SYNC`
- `OUTPUT`

不要把所有正文都写成这种风格，只用于标题、状态、分组。

## 10. Page-Level Application For 1Life

### 10.1 Dashboard

目标：像“今日身体账本总览”。

建议结构：

1. 顶部系统栏
2. 今日总热量主面板
3. 三大营养素分区条
4. 饮水 / 活动 / 目标差值的紧凑面板
5. 今日餐食记录条目预览

细化规则：

- 总热量数字必须是页面第一视觉中心
- 目标完成度用简洁线性条或环，不做花哨图表
- “剩余 / 超出”要做成明确状态值
- 卡片数量宁少勿碎

### 10.2 Food Timeline

目标：像“健康流水记录”。

建议：

- 每餐是一个分组面板
- 每个食物是条目行
- 热量数字始终右对齐
- 时间、来源、AI/手动等信息做成辅助标签

可加入：

- `AI LOG`
- `MANUAL`
- `PHOTO`
- `EST.`

### 10.3 AI Chat

目标：保留对话体验，但让 AI 识别结果更像“待确认分析输出”。

建议：

- 对话骨架必须继承 family 共享 `AI Chat` 结构
- 对话气泡依旧可用原生风格
- 识别结果必须升级为结构化面板
- 输出卡片中的每个食物行可单独编辑
- 底部确认操作区要像“提交记录”

### 10.4 My Life

目标：像个人行为与状态档案。

建议：

- 习惯区偏操作面板
- 日志区偏时间线档案
- 少做大情绪化插图
- 更强调“记录组织感”

### 10.5 Settings

目标：像系统配置中心。

设置页是最适合完整落地新风格的页面之一，原因是它天然符合参考图的面板气质。

同时，`Settings` 也是 family 级共享界面，`1Life` 不应单独发明一套设置页骨架。

建议：

- 强化分组标题
- 个人资料做成头部面板
- 每行设置项更像配置条目
- 右侧箭头、状态值、开关保持规则化对齐

---

## 11. Priority Refactor Order

如果开始实施，建议优先级如下：

1. `Settings`
2. `Dashboard`
3. `Food Timeline`
4. `AI Chat` 识别结果卡片
5. `My Life`

原因：

- `Settings` 最容易先建立新视觉语法
- `Dashboard` 能最快体现风格升级价值
- `Food Timeline` 最能巩固“记录面板”语言

## 12. Implementation Notes For SwiftUI

### 12.1 Prefer Building Blocks

建议后续抽出统一组件：

- `SystemPanel`
- `SystemSectionLabel`
- `MetricValueText`
- `RecordRow`
- `StatusTag`
- `SystemToolbarHeader`

### 12.2 Styling Rules

- 优先统一边框、圆角、间距 token
- 尽量减少每页单独发明视觉样式
- 对颜色、描边、标题样式做集中封装

### 12.3 Compatibility Rule

虽然新风格更硬朗，但仍需保持：

- iPhone 小屏可读
- Dynamic Type 不至于崩
- 触控区域足够大
- 原生交互习惯不被破坏

---

## 13. Non-Negotiables

以下是本轮 UI 升级必须坚持的点：

- 必须更有“系统面板感”
- 必须减少旧版的温和圆润感
- 必须让信息边界更清楚
- 必须建立统一的标签、状态、记录行语言
- 必须克制用色
- 必须优先提升设置页和首页的一致性

---

## 14. One-Sentence Summary

`1Life` V2 的界面应该看起来像一套为个人健康而设计的现代控制台：克制、清晰、可信、结构化，而不是一个常规的柔和健康打卡 App。
